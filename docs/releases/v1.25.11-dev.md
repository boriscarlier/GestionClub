# V1.25.11-dev - Acces reseau local controle

## Objectif

Permettre un test de Gestion Club depuis un autre appareil du meme reseau prive sans modifier le comportement local stable de V1.25.10.

## Architecture

- `DEMARRER_SERVEUR.cmd` reste le demarrage local par defaut sur `127.0.0.1`.
- `DEMARRER_RESEAU_LOCAL.cmd` active volontairement le mode LAN.
- `server/network_access.py` detecte les adresses IPv4 LAN et valide les en-tetes reseau.
- `server/lan_server.py` reutilise le serveur existant et ajoute la barriere LAN avant ses protections existantes.

## Protections

- clients IPv4 locaux/prives uniquement ;
- `Host` limite a la boucle locale et aux IPv4 LAN detectees ;
- `Origin` des requetes d'ecriture strictement identique au `Host` valide ;
- session, CSRF et roles geres par le serveur existant ;
- aucune regle pare-feu creee automatiquement ;
- aucune ouverture ou redirection routeur.

## Tests automatises

7 controles LAN sont ajoutes, portant la suite attendue de 89 a 96 tests.

La CI GitHub Actions execute la suite sur les branches `dev/**`, `main` et les pull requests.

## Validation physique requise avant release V1.25.11

1. Mettre a jour le dossier de test sans toucher a `data`.
2. Creer ou utiliser un compte de test, de preference `reader` pour le premier essai.
3. Fermer tout serveur deja lance sur le port `8765`.
4. Lancer `DEMARRER_RESEAU_LOCAL.cmd`.
5. Relever l'adresse `http://IP_PRIVEE:8765/` affichee.
6. Depuis un deuxieme appareil sur le meme reseau prive, ouvrir cette adresse.
7. Verifier connexion, consultation et refus d'ecriture du compte `reader`.
8. Ne pas ouvrir ni rediriger le port `8765` sur le routeur.

La version visible par l'application reste V1.25.10 tant que cette validation physique n'est pas terminee et que la release V1.25.11 n'est pas finalisee.
